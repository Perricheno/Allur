# Автодиспетчер — помощник поездного диспетчера для ГИД

Прототип интеллектуального модуля ГИД для КТЖ. Решает задачу из ТЗ: при нестандартной ситуации (сход, закрытие пути, движение по неправильному пути, ограничение скорости после ремонта) система находит конфликты, считает несколько вариантов пропуска с учётом приоритетов, предлагает лучший, после подтверждения диспетчером перестраивает прогноз и сообщает пассажирам об опоздании. Решение остаётся за диспетчером.

Node.js 22+, без сборки и без внешних зависимостей для запуска. Интерфейс: Preact + htm (файлы лежат в `public/vendor`), шрифт Inter (самохостинг), иконки Lucide с плавным морфингом через [morphicons](https://www.morphicons.com).

## Запуск

```sh
npm start          # http://127.0.0.1:3000, PORT=3001 меняет порт
npm run check      # синтаксис
npm test           # проверки модели (расписание, ТО, поломки, события)
npm run test:e2e   # браузерные тесты (нужен npx playwright install chromium)
KTZ_AUTOPLAY=0 npm start   # детерминированный режим для тестов: фиксированное время 09:00, события выключены, состояние не сохраняется
```

Модель живёт непрерывно: расписание строится из суточных шаблонов по текущему времени (смены нет), поезда появляются и уходят сами. Состояние общее для всех подключённых, сохраняется на диск (`data/state.json`, путь — `KTZ_STATE`) и переживает перезапуск сервера: за время простоя жизнь «догоняется». Кнопка сброса начинает всё с реального текущего момента.

## Страницы

`#/` Обстановка (живая схема участка с движущимися поездами, показатели, ГИД, кто стоит и почему) · `#/decisions` Решения (события, варианты, подтверждение, уведомления) · `#/trains` Поезда · `#/stations`, `#/station/D` Станции · `#/log` Журнал · `#/how` Как это работает (анимированные демонстрации, факторы, пошаговый алгоритм на реальном движке, три разобранных случая, песочница, станции и сроки доставки).

## Что умеет

- **Живая схема участка** (главный экран) в условных обозначениях схемы поездо-участков: станции с станционными путями, съездами и пассажирскими платформами, границы станций, поездо-участки с подписью, главные пути (нечётный красный ←, чётный синий →), входные и выходные светофоры станций, проходные светофоры автоблокировки (красные, когда блок занят или путь закрыт), подъездные (грузовые) пути станций с занятостью. Поезда движутся по модельному времени; стоящие на станции выделены красным и подписаны «стоит N мин» с причиной; сход показан на пути, ограничения скорости — знаками. Клик по поезду — где он, когда прибудет, почему стоит. Меню можно свернуть, чтобы схема стала крупнее.
- **Панель диспетчера** (под схемой): очередь задач (подтвердить вариант пропуска, поезда, которые стоят и ждут, прибывшие вагоны, риск просрочки доставки, опоздания пассажирских) с кнопками действий; вкладки «Поезд» (задержать на ближайшей станции на 5/10/20/30 мин, пропустить первым), «Станция» (пути, вагоны, приём групп) и «События» (закрытие перегона, ограничения скорости). Каждая команда пересчитывает прогноз и пишет в журнал, как изменилась суммарная задержка.
- **Непрерывные данные**: около 90 поездов в сутки (пассажирские, контейнерные, транзитные, сборные) по суточному расписанию; станции сами принимают прибывшие группы вагонов и убирают обработанные; случайные события (поломки, плановые окна на ремонт, ограничения скорости) происходят сами с выбираемой интенсивностью; «автопилот» применяет рекомендованный вариант пропуска, если диспетчер не вмешался за 15 минут.
- **Характеристики поездов**: локомотив (серия, тип, мощность), нагрузка и масса, длина, скорости, осевая нагрузка, бригада, топливо, тех. состояние; **техобслуживание**: у каждого рейса свой интервал (контейнерные — часто), поезд уходит в рейс после ТО; загрузка каждого перегона на ближайший час.
- **Поломки четырёх уровней**: 1 лёгкая (ограничение скорости до конца рейса), 2 средняя (остановка 15–40 мин и продолжение), 3 тяжёлая (поезд снят с рейса, путь перегона занят 1,5–3 ч), 4 критическая (сход, оба пути закрыты на 4–8 ч). Проецируются на выбранный поезд или случаются сами. Закрытия путей любого перегона и любого пути (нечётный, чётный, оба), в том числе запланированные «окна».
- **Ход времени**: по умолчанию реальное время (×1); для демонстрации можно ускорить ×60, ×180, ×600, кнопки +15 мин, +30 мин, +1 час перематывают вперёд. Ускорение действует, пока кто-то смотрит; потом время возвращается к обычному ходу. «К реальному» снова синхронизирует с часами, если модель не ушла вперёд.

- **ГИД**: 30 ниток на 10 станциях, масштаб 4/8/14 ч, прокрутка, фильтр по категории, подсказка при наведении, выделение поезда. Сплошная линия — прогноз, пунктир — нитка по графику, красный отрезок — ожидание на станции, штриховка — закрытый перегон.
- **Приоритеты**: 1 — пассажирские, 2 — контейнерные и транзитные, 3 — сборные и прочие грузовые.
- **Закрытие перегона D–E**: встречные конфликты на оставшемся пути, три варианта пропуска («По приоритету», «Пакетами по направлениям», «По очерёдности подхода»), метрики по каждому, рекомендация с объяснением, выбор и подтверждение.
- **Ограничения скорости** на любом перегоне (25/40/60 км/ч): пересчёт времени хода всех затронутых поездов.
- **Опоздания пассажирских**: прогноз прибытия и автоматическое уведомление пассажирам при изменении на 5 минут и больше.
- **Станции**: подъездные пути, обработка и уборка вагонов, подход групп вагонов, приоритет по остатку срока доставки, резервирование ёмкости, CSV.
- Адаптивная вёрстка (нижняя навигация на телефоне), клавиатурная навигация, ссылки на страницы вида `#/station/D/arrivals`.

## Модель расчёта

Файл `server/dispatch.js` — чистые функции. Нитка поезда — точки `[минуты от начала смены, индекс станции]`.

1. Время хода по перегону умножается на `80 / ограничение` (км/ч) и на 1,25 при движении по неправильному пути.
2. При закрытии перегона все поезда, идущие через него, делят один путь: встречные не могут быть на нём одновременно (зазор 3 мин), попутные идут с интервалом 6 мин.
3. Вариант пропуска — правило очерёдности входа на перегон. «По приоритету» удерживает груз на станции (не дольше 45 мин), если встречный более приоритетный подойдёт, пока груз ещё будет на перегоне.
4. Рекомендуется вариант с наименьшей взвешенной задержкой (вес пассажирского 10, транзитного 2, сборного 1).

Это объяснимая эвристика, а не оптимизатор и не проверенный график: интервальное регулирование, стрелочные маршруты, локомотивные бригады и сигналы не моделируются. Система не заменяет СЦБ.

## Структура

```text
server/index.js      HTTP, JSON API, SSE, статические файлы
server/model.js      состояние, действия, ход времени, уведомления, снимок для клиента
server/world.js      станции, суточное расписание, характеристики и ТО, автоматика, события
server/dispatch.js   прогноз, закрытия путей, поломки, конфликты, варианты пропуска
public/js/           main, store (состояние, маршрутизация), ГИД, решения, страницы,
                     how*.js (страница «Как это работает»), engine.js (движок в браузере)
public/styles/       tokens (дизайн-токены), base, app
deploy/              Docker Compose для ktz.perricheno.com
```

## API

- `GET /engine/model.js`, `/engine/dispatch.js` — тот же движок для песочницы в браузере.
- `GET /api/state` — снимок состояния; `GET /api/events` — SSE; `GET /healthz`.
- `POST /api/action` — действия: `advance` (`minutes` 15/30/60), `hold` (`train`, `minutes` 5/10/20/30), `release`/`expedite`/`restore` (`train`), `accept` (`groupId`: резерв и приём прибывшей группы), `clock` (`running`, `speed` 1/60/180/600, `sync`), `close` (`segment`, `track`, `minutes`), `reopen` (`id`), `breakdown` (`train`, `level` 1–4, `kind`), `auto` (`intensity`, `stations`, `approve`), `complete`/`clear` (`trackId`), `reserve`/`cancel`/`arrive` (`groupId`), `block`, `variant` (`variantId`), `approve`, `restrict` (`segment`, `kmh` 15–79), `unrestrict` (`segment`), `reset`. Ошибки — HTTP 400 с полем `error`.

Все данные синтетические; названия станций и расстояния не описывают реальную сеть.
